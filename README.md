一个基于 Web 技术开发的英语单词背诵应用，采用简化 SM-2 记忆曲线算法帮助用户高效记忆单词。纯前端实现（HTML/CSS/JS + localStorage），双击 `index.html` 即可运行，无需任何后端或构建工具。

## ✨ 功能特点（v1.0.1 现状）

### 📚 单词管理
- **搜索 & 添加**：在首页输入英文单词搜索；词库中已有则可补充新词性/释义，未命中则可录入新词（含词性 + 多条中文释义，逗号/顿号分隔自动拆分）
- **词库浏览**：顶部导航「词库」页查看全部单词，展示单词、所有词性释义、创建日期、最新一次背诵情况（v1.0.1 改用 DOM API + textContent 渲染，防 XSS）
- **词库统计**：首页「词库简略」区实时显示「词库总数 / 未背诵 / 待复习」三项

### 📝 背诵任务 & 记忆曲线
- **自定义任务**：每日任务可独立设置「新学数量」+「复习数量」，创建后可开始背诵；v1.0.1 起：同日已有任务时弹自定义 Modal 确认（继续原任务 / 重建覆盖），不再静默覆盖
- **简化 SM-2 算法**：每单词 10 轮复习（r1~r10），EaseFactor 初始 1.5；答对 +0.1，答错 -0.2，不熟 -0.1；按 `ceil(1 * EaseFactor^(轮次-1))` 动态推下次复习日；**v1.0.1 核心红线**：同一单词每日最多写入一条 rXR 记录（同日重背=原地覆盖，不再虚增轮次）
- **两种背诵模式**（背诵页可随时切换）：
  - 🇨🇳→🇬🇧 **中译英**：显示中文释义 → 手输英文单词（答案略对得上=「不熟」）
  - 🇬🇧→🇨🇳 **英译中**：显示英文单词 → 6 选 1 中文释义；**v1.0.1 三档视觉**：对=绿 `#4CAF50` / 不熟=橙 `#ff9800` / 错=红 `#f44336`，正确答案始终高亮绿色
- **快捷键**：背诵页 Enter 提交/下一题；0=对 / 8=不熟 / 9=错；英译中按 1~6 直接选选项；**v1.0.1 防误判**：input/textarea 聚焦时所有数字快捷键自动失效（仅保留 Enter 提交）
- **🆕 v1.0.1 紧急写库**：首次背诵当日任务时关浏览器/断电，onbeforeunload 自动调 completeTask 紧急保存进度；错题重测 / 重做今日计划未完成一轮时则按用户意愿不紧急写库，接受从头再来

### 🔁 错题与重开
- **查看背诵结果**：结果页分「首次背诵 / 错题重开 N 轮」展示，每轮分别显示 对/不熟/错 计数
- **三种重开方式**（UI 仍为两个独立按钮，底层已收口为统一 `retryWrongByMode(mode)` 入口 + 聚合状态 `DEFAULT_RETRY_STATE`）：
  - 🔄 **重新背诵今日计划**：完整重背今日新学+复习，原子操作「先清当日旧 rXR → 再写新成绩」，保证每日一轮红线
  - 🟧 **首次错题重测**：只重开「第一次背诵」中答错的单词（固定范围，可无限次重做）
  - 🟥 **错题重开**：从最近一轮错题开始，可无限轮次，直到全部答对（链式推进）
- **🆕 v1.0.1 关键语义**：**错题重测三种模式下一律不写词库**（纯练习，不影响 SRS 曲线），结果仅存入 `retryState.xxxResult` 供结果页对比展示

### 💾 数据导出类
- **导出今日单词表**（计划区，蓝色按钮）：创建任务后可导出当日新学+复习的单词+释义 JSON 摘要（**非完整备份**，仅供当日打印/复习）
- **导出今日结果**（结果页）：导出当次首次背诵 + 各轮错题重开结果 JSON 摘要（**非完整备份**）
- **🆕 导出背诵备份**（首页 → 系统设置 → 💾 绿色按钮）：**v1.0.0 新增**
  - 导出 **完整长期背诵数据**（词库 + 10 轮复习记录 + customDate 设置）
  - **不包含当日任务 todayTask**（属于当日临时数据，每次启动按当日日期重新生成）
  - 生成文件名：`NEWordRemberer_备份_YYYYMMDD_HHMMSS.json`
  - 下载后提示：文件在浏览器**默认下载目录**，按 Ctrl+J 查看

### 📥 数据导入类
- **🆕 导入背诵记录**（首页 → 系统设置 → 📥 蓝色按钮）：**v1.0.0 新增**
  - **双模式导入**（弹窗内 Tab 切换）：
    - 📁 **选择 JSON 文件**：选本地备份文件 → 自动解析校验
    - 📋 **粘贴 JSON 文本**：用任意编辑器打开备份 → 全选复制 → 粘到文本框（实时校验）
  - **严格文件身份校验**：自动识别「今日单词表 / 今日结果」等摘要文件，明确拒绝并提示"请使用 💾 导出背诵备份 功能生成的文件"
  - **版本兼容判断**（主版本号规则）：
    - 备份格式 == 当前（1.x ↔ 1.y）→ 完全兼容 ✅
    - 备份格式 < 当前（旧版导入）→ 兼容读取，字段缺失单词跳过 ⚠️
    - 备份格式 > 当前（新版导入到旧程序）→ 弹红色警告 + 二次确认，不保证新字段完整
  - **两种导入策略**（执行前 confirm 选择；v1.0.1 推荐合并=安全默认，覆盖=危险操作）：
    - **覆盖（overwrite）**：清空当前词库 → 写入备份；最后一次确认强提醒"请先导出备份"
    - **合并（merge）**：按单词小写去重；**v1.0.1 三级冲突优先级**：① 复习轮次更高者赢 → ② 轮次相同则 easeFactor 更低者赢 → ③ 轮次 / ef 均相同则本地当前词库优先；不同单词直接追加
  - **导入后汇总**：显示新增 / 被替换（合并模式）/ 跳过无效 / 当前词库总数
  - **🆕 v1.0.1 导入后清理**：无论覆盖还是合并，导入完成后立即清除 todayTask（避免旧当日任务与新词库 mismatch），UI 提示「已重置当日任务，请重新创建」

### ⚙️ 系统设置
- **自定义今日日期**：用于模拟调试记忆曲线算法（不影响真实系统时间），可不设置；v1.0.1 起日期范围扩展为 2000-01-01 ~ 当前年份+2-12-31，支持跨年到期测试；非法格式 / 不存在的日期（如 2026-13-40）会被拒绝写入并提示
- **清除所有背诵记录**（红色高危按钮）：仅清空 r1~r10 日期/结果字段，保留单词释义；v1.0.1 底层 API 已拆分：
  - `clearReviewRecordsOnly()`：只清 r1~r10（按钮当前调用此方法）
  - `factoryResetKeepDefaultWords()`：真正的恢复出厂（清词库回到默认 3146 词 + 清 customDate，供未来设置页「彻底重置」按钮使用）
- **🆕 版本号徽章**：标题栏右上角显示 `v1.0.1`，悬停显示 程序版本号 / 备份格式版本号

## 🚀 使用方法

1. **启动**：直接双击 `index.html` 用浏览器打开（推荐 Chrome / Edge）
2. **初始化**：首次使用自动加载 `data/defaultWords.js` 的 3146 词到 localStorage
3. **（可选）系统设置**：如需调试记忆曲线 → 设置自定义日期
4. **创建任务**：首页 → 计划区 → 填写「背诵/复习数量」→ 「创建任务」
5. **开始背诵**：创建后点击「开始背诵」进入背诵页
6. **查看结果**：背诵结束自动跳到结果页，可查看正确率、错题重开
7. **🆕 定期备份**：系统设置区 → 💾 导出背诵备份 → 将 JSON 文件保存到网盘/硬盘
8. **🆕 恢复数据**：换设备 / 清缓存后 → 📥 导入背诵记录 → 选 JSON 文件或粘贴内容 → 覆盖恢复

### 🔄 Schema 升级的 3 条铁律（备份格式变更时）

**铁律 1：`schemas` 对象永远只追加、不删除、不覆盖旧版本**
```
// ❌ 错误：直接改 schemas["1.0.0"] 的字段（破坏旧备份导入）
schemas["1.0.0"].wordObjectFields.r11D = ...;

// ✅ 正确：新增一个 schema 条目，并保留旧 schema 供老版本导入升级用
schemas["1.1.0"] = {
  version: "1.1.0",
  description: "扩展为 11 轮复习（新增 r11D/r11R）",
  // ... 完整新定义
};
```

**铁律 2：新版本必须提供向上升级函数 `upgradeFrom_<OLD>_To_<NEW>`**
```javascript
// 例子：旧备份 1.0.0 → 新格式 1.1.0
schemas["1.1.0"].upgradeFrom1_0_0 = function(data) {
  // 给每条 word 补上 r11D/r11R
  data.wordBank.forEach(w => {
    if (!('r11D' in w)) { w.r11D = ''; w.r11R = ''; }
  });
  return data;
};
```
然后在 `UIManager._validateAndShowInfo()` 或 `WordBank.importBackupData()` 入口处调用对应升级函数，保证**任何旧版本备份都能先升级成当前格式再写入**。

**铁律 3：导入兼容策略固化（别手改）**
| 对比结果 | 处理方式 |
|---|---|
| 旧格式 → 新程序（major 相同）| 先升级 → 再导入 |
| 旧格式 → 新程序（major 不同，如 1.x → 2.x）| 按条目写升级函数；兼容入口在 SchemaRegistry |
| 新格式 → 旧程序（major 更高）| 弹红色警告 + confirm；旧程序 `importBackupData` 只取 `data.wordBank` / `data.customDate` 两个已知字段，未知字段 JSON.parse 保留但忽略，不会报错 |

### 🧭 三边对照防错法（每次改格式都要检查）

**边1（代码·真相源）= SchemaRegistry**
- 检查 `schemas[newVer].wordObjectFields`、`validateWord` 与实际 WordObject 结构一致

**边2（JSON 内嵌）= `generateEmbeddedFormatDoc()` 输出**
- 导出一个 JSON → 打开看 `exportedFromFormat.schemaVersion` 是否 == 边1 的版本
- 检查 `exportedFromFormat.wordObjectFields` 每一条描述是否 == 边1 的 type + desc

**边3（文档）= `BACKUP_FORMAT.md`**
- 打开文档 → 对比顶部「备份格式版本」和「WordObject 字段表」是否与边1 一致

三边任何一对不一致 → 说明版本更新时漏改位点，**立即回滚修复后再提交**。

---

### 📤 todayTask 不属于备份范围（设计原则）

- **原因**：todayTask 是「当日一次性产物」，日期变化后旧任务立即失效（TaskManager.getTodayTask 会比对日期）
- **后果**：导入备份**不恢复 todayTask**（即使 JSON 里有也不写入），避免污染当日正在进行的任务
- **迁移后恢复流程**：换设备恢复备份 → 重新「创建任务」→ 程序按当日日期 + customDate 自动筛选未背/待复习单词
